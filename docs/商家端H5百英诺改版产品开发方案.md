## 1. 背景与目标

### 1.1 背景

商家端 H5 当前为「工作台」风格（hero + 指标卡 + 待办 + 九宫格 + 退出登录），视觉与 C 端商城差异大、无品牌露出。业务要求：

1. 参照中云严选小程序的 4 个页面样式，对商家端 H5 进行全面视觉与结构改版；
2. 首页承担「功能门户 + 品牌阵地」双重职责：提供全部业务功能入口，并依据企业内部资料植入「百英诺」品牌介绍；
3. 品牌为 **百英诺**（武汉百英诺生物科技有限公司，同济医院孵化的菌群移植 FMT 成果转化企业）。

### 1.2 目标

- 商家打开 H5 后，第一屏即可感知百英诺品牌（主视觉 banner + 品牌色），并可在 2 次点击内到达任意业务功能；
- 采购链路（商品浏览 → 加购 → 结算）交互与参考小程序对齐，降低商家学习成本；
- 新增「我的」个人中心页，沉淀账户、采购单状态、应用入口与退出登录；
- 全部文案符合医疗/大健康广告合规口径（见 §12）。

### 1.3 非目标（本期不做）

- 不改后端业务逻辑与佣金/对账链路；
- 不做 C 端营销玩法（积分商城、签到、优惠券核销——商家端不适用，以预付款体系替代，见 §6.6）；
- 不做商品分类后台管理（初版前端常量，见决策点 D4）；
- 不动 weapp 端配置（本次仅 H5 验收，但代码保持双端可编译）。

## 3. 商家端现状与差距分析

当前首页 `apps/mini-b/src/pages/index/index.tsx` 结构：hero（角色/问候/预付款余额）→ 今日经营（3 指标）→ 今日待办（4 行）→ 快捷入口（9 宫格 emoji 图标）→ 退出登录。采购页 `apps/mini-b/src/pages/procurement/index.tsx` 为简单商品列表 + 采购单列表（约 150 行）。

| 参考页 | 商家端对应 | 现状 | 差距 |
|--------|-----------|------|------|
| 首页 | `pages/index` | 有宫格与指标卡 | 无品牌 banner、无公告、无客服卡、无品牌介绍区、无搜索条、图标为 emoji 而非彩色圆图标 |
| 商品列表 | `pages/procurement` | 单列文本卡片 | 无分类侧栏、无子类 pill、无商品图/资质标签/划线价、无「+」加购 |
| 购物车 | 无 | 采购单直接生成 | 无加购-结算交互、无底部结算条 |
| 登录弹窗 | `pages/login` | 全页表单 | 非卡片式、无协议勾选行、无品牌 logo 位 |
| 我的 | 无 | 首页内嵌退出 | 无独立个人中心页 |
| 全局 | `app.config.ts` | 无 tabBar，单页跳转 | 无底部 4 Tab 导航 |

## 5. 信息架构调整：新增底部 4 Tab

| Tab | 页面 | 说明 |
|-----|------|------|
| 首页 | `pages/index/index` | 品牌门户 + 功能入口 + 经营概览 |
| 采购商城 | `pages/procurement/index` | 商品浏览 / 加购 / 结算 |
| 消息 | `pages/notifications/index` | 公告 / 待办 / 报告任务 |
| 我的 | `pages/profile/index`（**新增**） | 账户 / 采购单 / 应用 / 退出 |

**实现方式（决策点 D2，推荐方案）**：H5 端不走 Taro 原生 `tabBar` 配置（需 8 张 PNG 图标资源、weapp/H5 表现不一致），改为自绘 `components/AppTabbar.tsx`（基于 NutUI `Tabbar`），在 4 个 tab 页底部挂载；选中态用主紫，图标用 NutUI 图标或线性 SVG（弃用 emoji，对齐参考样式）。其余页面仍用 `navigateTo` 跳转，底栏仅在 4 个 tab 页出现。

`app.config.ts` 仅需在 `pages` 数组注册 `pages/profile/index`，`window.navigationBarBackgroundColor` 随主题决策（§7）调整。

## 6. 页面改造详细方案

### 6.2 采购商城 `pages/procurement/index.tsx`（对齐商品列表页）

1. 顶部：紫色导航标题「采购商城」+ 搜索条（前端过滤商品名/SKU）
2. **左侧一级分类侧栏** + **顶部二级 pill**（分类来源见决策点 D4；初版前端常量，如：检测服务 / 移植产品 / 健康消费品 / 定制化产品 / 配套辅剂）
3. **商品卡重构**：
   - 左：72px 缩略块（无图时用渐变块 + 商品名前两字，沿用 mini-c 的 `product-thumb` 模式；`Product` 有图后接图）
   - 右：名称 2 行截断 + 红色资质标签（如「GMP」「同济共建菌库」，前端按品类映射常量）+ 主价格（主色大字 `price-main`）+ 划线建议零售价 + 「渠道专享价」黑色标签（如有差价）
   - 右下角主色圆形「+」按钮 → 加入采购车（本地 state + storage 持久化即可，体量小不引入新状态库）
4. **底部固定结算条**（参照购物车）：已选 N 件 + 合计（红字）+ 主色「去结算」胶囊 → 进入采购确认浮层（收货信息 + 提交生成采购单，复用现有下单 API）
5. 「我的采购单」列表下沉为页面下半区（或 Tab 切换「可采商品 / 我的采购单」）

### 6.3 登录页 `pages/login/index.tsx`（对齐登录弹窗）

- 全页浅灰底 + 居中白卡片（参照弹窗结构）：顶部品牌 logo 圆标位（`【LOGO】`占位，120×120 圆）+「欢迎登录」+「登录后可享受更好的服务体验」
- 协议勾选行：已阅读并同意《服务协议》与《隐私政策》（未勾选禁登，Toast 提示）
- 主按钮改紫色渐变胶囊「登录」；保留现有账号密码表单字段与 `ensureLogin` 逻辑不变
- 协议文档为静态文案页或外链（初版静态，后续接 admin 配置）

## 12. 合规要求（红线）

1. 品牌区仅陈述资料内事实（成立时间、资质、专利数等），禁止疗效承诺用语（治愈、根治、有效率 xx%）；
2. 健康消费品（英诺衡/英诺畅/益君酣/英诺纤）按特殊膳食/食品口径表述，不得宣称治疗功能；
3. 移植类产品页面须带「须在执业医师指导下使用」提示；首页固定 §4.2 合规声明；
4. 资质图标须使用真实证书图（企业提供并授权），不得用通用图标冒充；
5. 《服务协议》《隐私政策》上线前需法务审定文本。
