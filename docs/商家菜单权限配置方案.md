# 后台管理端 · 商家菜单权限配置方案

> 分支：`feat/merchant-menu-permissions`（worktree 开发后合并回 main）
> 日期：2026-10-28

## 1. 工作流程（git worktree）

1. `git worktree add ../.worktrees/mall-merchant-menus -b feat/merchant-menu-permissions`，在独立目录开发，不污染主工作区未提交改动。
2. worktree 内使用独立的 `.env`（独立数据库端口 5434、API 端口 3100），与本地已启动服务（postgres 5433 / api 3000 / mini-b 10086）完全隔离。
3. 开发完成 → 全量验证（单测 + e2e + 三端 typecheck + 新端口起服务冒烟）→ 合并回 `main` → 清理 worktree。

## 2. 功能范围

平台运营（`platform`）在后台「账号与资质」页为**已入驻**的商家主账号分配商家端（mini-b）可见菜单：

- **分配/修改/保存**：操作列新增「菜单权限」入口，弹窗内勾选菜单目录项，保存即生效（upsert，无需重启）。
- **商家数据关联**：
  - 仅 `primaryRole = merchant` 的账号可配置，且账号状态与所属组织状态均为 `active`（即审核通过、已入驻）。
  - **销售账号继承**：同组织商家主账号的配置对组织内销售生效；无配置时销售同样拿默认全量。
- **生效端**：商家端首页宫格 10 个功能入口、首页待办卡、「我的」页应用宫格按权限过滤。底部 4 个页签（首页/采购商城/购物车/我的）为平台核心能力，不参与配置。

## 3. 权限模型与校验规则

- **目录制（白名单）**：菜单目录唯一来源是 `packages/shared/src/merchant-menus.ts` 的 `MERCHANT_MENU_ITEMS`（10 项：采购商城、预付款、我的客户、健康助手、报告与解读、我的生意、素材与培训、课程与考试、业务流程、客户认领）。后台选项与商家端过滤都从这里取，避免两端目录漂移。
- **默认全量（fail-open）**：未保存过配置的商家 = 全量菜单，存量商家行为不变；商家端拉取配置失败时也不隐藏菜单。
- **保存校验**（API 层 `validateMerchantMenus`）：
  - 必须为字符串数组（DTO `@IsArray @IsString(each)` 兜底中文报错）；
  - 拒绝目录外 key（提示 `包含未知菜单项：xxx`）；
  - 自动去重并按目录顺序归一；
  - 允许空数组 = 关闭全部可选菜单（后台二次确认防误操作）。
- **鉴权**：
  - `GET/PUT /api/merchant-menus/:merchantId` → `@Roles(PLATFORM)`（RolesGuard 平台直通，其余角色 403 并留痕）；
  - `GET /api/merchant-menus/me` → `@Roles(MERCHANT, SALES)`，其他角色 `ForbiddenException`；
- **审计**：每次保存写 `AuditLog`（`action=merchant_menu.updated`，detail 记录 before/after）。

## 4. 数据表与接口改动

### 数据表（Prisma 新增迁移 `20261027200000_merchant_menu_permissions`）

```prisma
model MerchantMenuPermission {
  id         String   @id @default(cuid())
  merchantId String   @unique            // 1 个商家主账号 1 条记录
  merchant   User     @relation(..., onDelete: Cascade)
  menus      String[]                    // 目录内 key（PostgreSQL 原生数组）
  updatedBy  String?                     // 最近保存的平台运营账号
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt
}
```

`User` 增加 `menuPermission MerchantMenuPermission?` 反向关联。SQLite/MySQL 由既有 `prisma-runtime.mjs` 自动降级为 Json，无需额外处理。

### 接口

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/merchant-menus/:merchantId` | platform | 查询；未配置返回 `{ isDefault: true, menus: 全量 }` |
| PUT | `/api/merchant-menus/:merchantId` | platform | 保存 `{ menus: string[] }`，upsert + 审计 |
| GET | `/api/merchant-menus/me` | merchant/sales | 商家端生效菜单（销售继承组织配置） |

新增模块：`apps/api/src/merchant-menus/`（controller / service / dto），已注册进 `AppModule`。

### 前端改动

- `apps/admin`：`AccountsPage.tsx` 增加菜单权限弹窗（加载现值 → 勾选 → 保存；空选二次确认）。
- `apps/mini-b`：`lib/merchant-menus.ts`（带 60s 缓存的加载器 + fail-open 过滤器）；首页宫格/待办与「我的」页应用宫格按 `isMerchantPathAllowed` 过滤；登录/退出清缓存。

## 5. 完成后的验证方式

1. **单测**：`pnpm --filter @mall/api test`（新增 `merchant-menus.service.spec.ts` 13 例：目录校验、入驻校验、归一化 upsert、审计、销售继承、角色拒绝）。
2. **e2e**：`pnpm --filter @mall/api test:e2e`（新增 `merchant-menus.e2e-spec.ts`：真实建号审核 → 保存/校验失败 → 商家端 me 生效 → 销售继承 → 审计落库）。
3. **类型检查**：`pnpm typecheck`（shared / api / admin / mini-b 全绿）。
4. **隔离环境冒烟**：新起 postgres(5434) + api(3100)（不用本地已启动服务），`migrate deploy` + `seed` 后 curl 走通登录 → 查询默认全量 → 非法 key 400 → 保存 → 商家端 me 返回所选菜单。
5. **界面验证**：后台 `vite dev`（5174，代理 3100）打开账号页验证弹窗；商家端 H5 登录验证首页宫格按权限隐藏。
