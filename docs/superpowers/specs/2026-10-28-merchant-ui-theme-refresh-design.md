# 商家端双主题 UI 升级设计

## 目标

在不改变路由、业务字段和核心操作流程的前提下，升级商家端 H5 与微信小程序的「曜石黑金」和「经典蓝紫」主题，使两套主题共享同一组件骨架、信息层级和交互状态，并改善首页经营效率、商品图片展示、按钮、卡片、导航栏与表单的一致性。

## 设计原则

- 商家端是高频经营工具，优先级为效率、清晰、可信，其次才是装饰性品牌表达。
- 两套主题只更换语义颜色与材质，不改变组件尺寸、布局、文案或交互。
- 黑金主题使用克制的香槟金作为关键强调，普通卡片不得全部描金或发光。
- 经典蓝紫降低饱和度与大面积渐变使用，形成稳定、轻盈的长期操作界面。
- 所有页面颜色通过 `themePacks` 与 `--mall-*` 语义变量提供，页面组件不得新增写死主题色。
- H5 与小程序共享 Taro 组件和 SCSS；H5 可以增强毛玻璃、焦点态与宽屏壳，小程序必须有不透明降级和安全区适配。

## 组件规范

- 页面横向内边距 12px，区块间距 20px，卡片内边距 14px。
- 卡片圆角 16px，输入框与按钮 12px，标签 6px，弹层顶部 24px。
- 主按钮 48px，常规按钮 40px，紧凑按钮 32px；金底使用深色文字，紫底使用白字。
- 图标使用统一的 24 格圆角线性风格，导航 22px、功能入口 24px、列表操作 20px。
- 图标底衬为 44px 圆角方形。主题色只用于主入口，业务状态使用成功、警告、错误语义色。
- 输入框标签在上，错误信息在下；聚焦、禁用、加载、空状态与错误状态完整。
- 底栏保持四项，图标、文字和顶部短指示共同表达选中态，并预留底部安全区。

## 页面调整

### 首页

- 顶部经营区保留商家名称、角色、通知、预付款与搜索，压缩重复身份信息。
- 今日订单、今日收入、待处理合并为一张经营指标卡，主指标与辅助指标形成层级。
- 快捷入口首屏只显示五个高频操作，其余入口收进「全部应用」展开区。
- Banner 使用固定结构，限制为一个标题、一句说明和一个动作，预留未来真实业务图片位。
- 待办与热销优先于品牌介绍，品牌介绍继续保留但降低首屏权重。

### 商品展示

- 商品详情首图使用 4:3 中性图片舞台，避免白底包装直接贴在黑色画布上。
- 列表缩略图固定 1:1，统一留白、圆角与加载骨架。
- 无图时使用稳定的品牌化占位，不使用高饱和渐变。
- 分类、资质和状态标签位于信息区，不覆盖产品图。

## 双端适配

- 320px 到 430px 保持移动单列；H5 超过 768px 时使用最大宽度 520px 的居中应用壳。
- H5 支持 `:focus-visible`、细滚动条和半透明底栏；小程序使用不透明降级。
- 所有固定底部操作均使用 `env(safe-area-inset-bottom)`。
- 主题切换同步页面、导航栏、弹层、Toast 与原生输入框颜色。

## 非目标

- 不修改 API、数据库、路由、主导航标签与表单字段顺序。
- 不更换 Taro 或 NutUI，不引入新的图标或动画依赖。
- 不制作未经业务审核的医疗功效图片或宣传文案。

## 验收

- H5 和微信小程序构建通过，TypeScript 检查通过。
- 双主题令牌完整且主题切换后没有残留旧色。
- 首页、采购列表、商品详情、购物车、定价、表单、弹层与底栏均覆盖两套主题。
- 320px、375px、430px 与 H5 宽屏无横向溢出，底部安全区正常。
- 关键文字、按钮与表单达到 WCAG AA 对比度目标。
