## 1. 背景与现状

### 1.1 一期改版已落地（本方案的基线）

对照《商家端H5百英诺改版产品开发方案》，以下内容**已实现**，本方案不再重复：

- 首页：紫色沉浸头部 + 搜索条 + Banner 轮播 + 10 宫格 + 公告条 + 品牌介绍「走进百英诺」+ 商务联系卡（`apps/mini-b/src/pages/index/index.tsx`）；
- 底部 4 Tab 自绘导航（首页 / 采购商城 / 购物车 / 我的，`apps/mini-b/src/components/AppTabbar.tsx`）；
- 采购页：左侧一级分类侧栏 + 二级 pill + 双 Tab（可采商品 / 我的采购单）+ 底部结算条；
- 我的页、卡片式登录页、购物车本地持久化（`src/lib/cart.ts`）。

### 1.2 本次要解决的四个核心短板

经代码核查，与用户要求「每个商品均配有图片、完整的商品详情与介绍，统一布局结构，完善业务流程与信息展示」对照，当前差距如下：

| #  | 短板             | 现状证据                                                                                                                                                                     |
| -- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| G1 | **商品无图片**      | `Product` 模型无图片字段（`apps/api/prisma/schema.prisma:228-258`），前端商品卡用「商品名前两字渐变占位块」（`apps/mini-b/src/pages/procurement/index.tsx:221`），与参考小程序「方形商品图」差距最大                      |
| G2 | **商品详情不完整**    | 详情仅 `intro` 一段文本 + `guideVideoUrl`；`testItems/sampleType/samplingMethod/storageCondition/shelfLifeDays` 等已落库字段未在任何页面展示；**无商品详情页**（13 个注册页面中无 product-detail），用户无法从列表进入详情 |
| G3 | **商品库不全、分类靠猜** | 种子仅 6 个商品（`apps/api/prisma/seed.ts:637-702`），而归档转化方案已整理 **13 条**商品文案；分类用商品名关键词匹配（`MALL_CATEGORIES` 前端常量），无法保证每个商品归类准确                                                    |
| G4 | **业务流程信息缺失**   | 采购单 8 个状态（`ProcurementStatus`）仅显示文字标签，无进度可视化；「采购履约 → 样本检测 → 报告解读」三条企业核心业务流程没有任何页面承载；企业资质/科研背书信息散落在首页品牌区，不完整                                                              |

### 1.3 目标

1. **商品 100% 有图**：所有商品具备主图 + 详情图，列表、购物车、订单、详情页统一展示；无图数据有品牌化兜底，不破版；
2. **商品 100% 有完整详情**：新增商品详情页，聚合规格参数、图文介绍、采样指导视频、搭配推荐、关联培训、合规声明六类信息；
3. **商品库与企业真实产品线一致**：商品数 6 → 13，覆盖检测 / 移植 / 健康消费品 / 定制四大产品线；分类改为结构化字段，点击侧栏必出正确商品；
4. **业务流程可视可查**：采购单全状态进度条；新增「服务与履约指南」承载三条核心业务流程；「走进百英诺」升级为完整企业信息区（资质、科研、产品线）；
5. **布局结构统一**：商品卡、状态标签、页面头部、间距字号收敛为统一组件与 tokens，三页（首页/列表/详情）内容层级与参考小程序逐层对齐。

### 1.4 非目标（本期不做）

- 不改佣金 / 对账 / 预付款结算等金融链路逻辑；
- 不做真实物流轨迹对接（快递 100），仅沿用现有运单号展示；
- 不做商品评论、拼团、秒杀等营销玩法；
- 不做 OSS/CDN 选型切换（图片先落本地静态目录，接口预留 URL 化，见 §6 决策点）；
- 不动 weapp 发布配置，验收以 H5 为准，代码保持双端可编译。

## 3. 主要改动点

### 3.1 改动一：商品图片体系（对齐 G1）

**数据库**（`schema.prisma` → migration `product_images_category`）：

```prisma
model Product {
  // 新增
  images    String[] @default([])   // 有序主图+详情图 URL 列表，images[0] 为列表主图
  category  String?                  // 结构化分类 key，对齐前端 MALL_CATEGORIES
}
```

**图片资源方案**：

1. 从 `docs/归档/` 的《FMT产品介绍》PPT/PDF、《菌群移植项目介绍》PPT 中导出各产品实物/包装图（每商品 1 张主图 + 2~3 张场景/细节图），统一压缩至宽 750px、WebP 格式；
2. 存放 `apps/api/uploads/products/{skuCode}/01.webp…`，NestJS 以 `ServeStaticModule` 暴露 `/uploads/**`，DB 存相对 URL；
3. 上线正式图前，seed 数据先用「品类示意图 + 品牌水印」占位图，保证演示完整性；
4. admin 端 `ProductsPage` 增加图片维护区（上传/排序/删除），走现有 `PATCH /products/:id/content` 扩展字段。

**前端展示与兜底**：

| 场景        | 展示方式                    | 无图兜底                         |
| --------- | ----------------------- | ---------------------------- |
| 列表商品卡     | 96×96 圆角方形图（参考小程序同尺寸）   | 品牌紫渐变占位块 + 商品名首字（沿用现有块，抽成组件） |
| 详情页头图     | Swiper 轮播，比例 1:1，支持双指放大 | 同上                           |
| 购物车/采购单条目 | 64×64 缩略图               | 同上                           |
| 我的页订单条目   | 48×48 缩略图               | 同上                           |

> 约束：一律 `Image mode="aspectFill"`，禁止拉伸；`shared/tokens.ts` 增 `--mall-image-radius: 8px` 令牌，三端统一。

### 3.2 改动二：商品详情页（对齐 G2，本期最大新增）

新增 `apps/mini-b/src/pages/product-detail/index.tsx`（注册进 `app.config.ts`，路由 `/pages/product-detail/index?id=xxx`，数据走现有 `GET /products/:id`），页面自上而下结构完全对齐参考小程序商品卡与医疗电商详情惯例：

1. **头图轮播**：images Swiper + 指示点；
2. **商品信息卡**：名称（2 行）+ 资质标签行（`PRODUCT_TAGS`，红底白字，如「GMP+P2 制备」「同济共建菌库」）+ 供货价大字红色 + 建议零售价划线 + 库存/批次信息；
3. **规格参数表**（灰底信息条，逐行键值对，数据全部来自已落库字段，不新增采集）：

| 参数          | 来源字段                    |
| ----------- | ----------------------- |
| 检测项目 / 主要成分 | `testItems[]`           |
| 样本类型        | `sampleType`            |
| 采样/使用方式     | `samplingMethod`        |
| 储存条件        | `storageCondition`      |
| 保质期         | `shelfLifeDays`         |
| 供货周期        | 批次/资料备注（转化方案 2.13 统一元素） |

1. **图文详情**：`intro` 按空行分段渲染 + 详情图（images[1..]）；富文本本期用结构化段落（安全、双端一致），不引入 HTML 渲染；
2. **采样/使用指导视频**：`guideVideoUrl` 有值时展示视频卡（对应转化方案 P0「试剂盒绑定采样视频 54.MP4」）；
3. **搭配推荐**：`relatedLinks`（如 FMT 胶囊 ↔ 专用辅剂、疗程 ↔ 微移植胶囊，依据转化方案 §4.1）横滑商品卡，点击跳详情；
4. **关联培训**：`courseBindings`（如采样规范课程）入口卡，跳培训页对应课程；
5. **合规声明条**：每页固定底部声明（严肃医疗商品「须在执业医师指导下使用」；大健康商品「普通食品/非疾病治疗用途」），文案取自转化方案 2.13；
6. **底部操作条**：「加入采购车」+「立即采购」，复用 `src/lib/cart.ts`。

**接口配套**：`GET /products/:id` 返回体补充 `images/category/relatedLinks(含对方名称与主图)/courseBindings`；列表接口 `GET /products` 增加 `images[0]`、`category`。

### 3.3 改动三：商品库补全与分类结构化（对齐 G3）

**商品 6 → 13**：按《归档资料整理与内容转化方案》第二部分 13 条文案逐条建品（文案与数据依据见该文档，不得虚构），新增 7 个：

| 新增 SKU（建议）       | 商品              | 产品线  | 依据       |
| ---------------- | --------------- | ---- | -------- |
| FMT-CAP-002      | FMT 菌群胶囊（升级版）   | 移植   | 转化方案 2.2 |
| FMT-PASTE-001    | FMT 菌泥          | 移植   | 2.3      |
| FMT-CAP-CUST-001 | 定制化活菌胶囊         | 定制   | 2.5      |
| FMT-FLUID-001    | 益生菌元液           | 定制   | 2.6      |
| INNO-HENG-001    | 英诺衡益生菌冻干粉（腹泻方向） | 健康消费 | 2.7      |
| INNO-CHANG-001   | 英诺畅益生元（便秘方向）    | 健康消费 | 2.8      |
| INNO-XIAN-001    | 英诺纤膳食纤维（体重管理）   | 健康消费 | 2.10     |

（益君酣 2.9、家庭采样装 2.12 视 SKU 规划评审结论并入或延后。）每个商品补齐：价格、testItems、sampleType、samplingMethod、storageCondition、shelfLifeDays、intro（直接采用转化方案文案）、images、relatedLinks（按 §4.1 搭配表）、courseBindings（按 §4.2 绑定表）。

**分类结构化**：

- `category` 枚举对齐参考小程序侧栏 + 企业产品线：`gut_test`（肠道菌群检测）/ `fmt`（菌群移植）/ `adjunct`（移植配套）/ `consumer_health`（健康消费）/ `customized`（定制产品）/ `training_kit`（采样耗材）；
- 前端 `MALL_CATEGORIES` 改为与该枚举同源的常量映射；列表页侧栏不再按商品名关键词猜归类，二级 pill 由「该分类商品的共同属性」生成（如检测类：标准版/极速版/家庭装）；
- 兜底：`category` 为空的商品归入「全部」，不丢失。

### 3.4 改动四：布局结构统一（对齐 G1/G3 视觉层）

原则：**组件收敛 + tokens 收敛**，让首页 / 列表 / 详情 / 购物车 / 我的五页的卡片、标签、间距、字号与参考小程序层级一致：

1. 抽取 4 个公共组件（`apps/mini-b/src/components/goods/`）：
   - `GoodsCard`：列表商品卡（图 + 标签 + 名称 + 价格行 + 加购「+」），首页推荐位与采购页复用；
   - `GoodsThumb`：缩略图组件（含品牌渐变兜底），购物车/订单/详情复用；
   - `StatusTag`：状态标签（采购 8 态、销售单 12 态统一色板：待处理橙 / 进行中蓝 / 已完成绿 / 异常红）；
   - `SpecList`：规格参数键值表（详情页与购物车确认页复用）。
2. 页面头部统一：紫底导航 + 白字标题 + 搜索条（仅列表/首页）规格写进 `components/PageHeader`，消除各页手写差异；
3. 样式令牌：间距统一 12px 卡片间距、字号 20/16/14/12 四档、价格色 `#FF3B30`、主紫 `#6E5CFF/#4C3ED9`，全部经 `packages/shared/src/tokens.ts` 引用（新增 `violet7` 派生令牌与 `--mall-price` 语义令牌）；
4. 内容层级对齐参考小程序：首页「banner → 宫格 → 优惠/活动 → 客服 → 公告」、列表「侧栏 → pill → 商品流」、我的「用户卡 → 统计 → 订单 → 应用宫格」结构不变，只做密度与组件级修正。

### 3.5 改动五：业务流程与信息展示完善（对齐 G4）

**5a. 采购单全流程进度可视化**（采购页「我的采购单」Tab + 采购单详情）：

`ProcurementStatus` 8 态映射为五节点进度条（参考小程序订单状态图标行样式）：

```
提交采购单 → 预付款扣款 → 商家发货 → 确认收货 → 完成
  (created)    (deducted)  (shipped)  (received) (completed)
侧支状态：待发货 pending_shipment / 售后中 after_sale / 已退款 refunded → StatusTag 单独标红/标橙
```

每单展示：进度条 + 当前节点高亮 + 关键时间（扣款/发货/收货时间）+ 运单号。

**5b. 新增「服务与履约指南」页**（`pages/guide/`，入口：首页宫格「业务流程」+ 品牌区「查看流程」）：

依据转化方案 §4.3 业务流程链路，三条流程以纵向步骤图呈现（内容全部取自企业资料，不虚构）：

1. **采购履约流程**：选购加购 → 预付款结算 → 平台发货 → 收货确认 →（如适用）盒码激活；
2. **样本检测流程**（面向商家的客户服务视角）：盒码激活 → 客户居家采样（附采样视频 54.MP4 入口）→ 样本寄回 → 实验室检测（收样后标准版 7-10 / 极速版 3-5 个工作日）→ 报告出具 → 专业解读；
3. **售后与咨询流程**：联系商务/客服 → 问题分类（检测/移植/报告/物流）→ 百问百答自助 → 专人跟进。

**5c. 「走进百英诺」企业信息区升级**（首页品牌区）：

- 现有 `BRAND_STORY`/`BRAND_STATS` 基础上补两张卡：
  - **资质与背书**：GMP 生产质量管理规范、P2 实验室、ISO9001、SC 认证、同济医院首家成果转化企业、政策编码 KPH3M401；
  - **产品线导览**：`PRODUCT_LINES` 4 条线改为可点击，点击跳转采购页对应分类（与 3.3 分类枚举打通）；
- 数据均出自归档资料 1.2「平台背景」，见转化方案出处标注。

**5d. 我的页信息层级微调**：

- 订单桶 `PROFILE_ORDER_BUCKETS` 状态口径与 `ProcurementStatus` 对齐（待发货/待收货/已完成/售后），点击带状态过滤跳采购单列表；
- 「我的应用」宫格补「业务流程」（跳指南页）与「企业介绍」（跳品牌区锚点）入口，替换低频占位项。

### 3.6 改动六：API 与管理后台配套

| 项                             | 内容                                                                                                        |
| ----------------------------- | --------------------------------------------------------------------------------------------------------- |
| Migration                     | `product_images_category`：Product 增 `images String[]`、`category String?`                                  |

### 9.2 关键实现细节

1. **分类唯一来源**：`packages/shared/src/product.ts` 定义 `PRODUCT_CATEGORIES`（6 类）与 `productCategoryLabel`，API 校验、商家端侧栏、管理端下拉三处共用，避免再次出现「前端常量 + 关键词猜测」。
2. **图片 URL 约定**：数据库存相对路径 `/uploads/products/{sku}/01.jpg`；商家端 `resolveAsset()` 补全域名，管理端走 Vite `/uploads` 代理；后续切 OSS 只改前缀（D1）。
3. **无图兜底**：`GoodsThumb` 对空值或 `onError` 统一渲染品牌紫渐变 + 商品首字，列表 / 购物车 / 详情 / 推荐位共用，保证任何脏数据不破版（验收 A3）。
4. **商家详情权限**：`GET /products/:id` 新增 merchant 分支，返回供货价与内容字段，但不下发平台服务费率、佣金上限等敏感字段；未上架商品仍返回 404。
5. **采购进度映射**：`ProcurementStatus` 8 态 → 五节点（提交 / 扣款 / 发货 / 收货 / 完成）；`cancelled / after_sale / refunded` 作为侧支状态单独展示，不进入进度条（验收 A5 手工核对 15 条历史采购单）。
6. **合规声明按分类下发**：详情页底部声明由 `category` 决定（严肃医疗 / 普通食品 / 检测报告），文案逐字取自归档转化方案 §2.13 与模块 7。

### 9.3 与方案的偏差（已确认取舍）

| 项 | 方案 | 实际 | 原因 |
|----|------|------|------|
| 图片上传 | admin 支持上传 | 先支持 URL 维护 + 本地静态目录 | 上传需引入 multer 与存储选型（D1），本期以「URL 可维护」达成 P0；上传列入待确认 |
| 详情富文本 | 结构化段落 | 同方案 | 不引 HTML 渲染，双端一致、合规可控（D2） |
| 采购单详情 | 独立详情页 | 列表内展开进度与明细 | 现有接口已含 items/时间，独立页收益低；后续按需拆分 |
| 购物车规格 | 复用 SpecList | 展示 SKU + 样本类型摘要 | 购物车空间有限，完整规格在详情页呈现 |

### 9.4 待确认事项（需业务 / 企业确认）

1. **新增 7 个商品价格为演示值**（升级版 3999/7999、菌泥 1999/3999、定制胶囊 5999/10999、元液 899/1799、英诺衡 129/259、英诺畅/纤 99/199 元），需企业价格体系确认后调整 seed 或后台改价。C 端售价已按「采购价 × 2」默认生成，商家可在「商品定价」页自定义（见 `docs/C端小程序商品与定价统一优化方案.md`）。
